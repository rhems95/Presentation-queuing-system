Current Domain Schema (students and settings included)

services

  • service_name, prefix
  • ticket type for Cashier, Registrar, DMO

windows

  • window_name, group_name, status
  • service_id — Cashier 1–3 share Cashier

users

  • role: admin | staff | guard
  • staff window_id unique; guard cannot log in

students

  • student_id, name
  • kiosk confirm lookup; name not stored on ticket

settings

  • setting_key / setting_value
  • walkin_pin for kiosk walk-in (not printed)

daily_queue_counters

  • service_id + queue_date
  • locked increment of last_number

queues

  • queue_number, service_id, priority, status
  • optional student_id; walk-in issued_by / issue_reason
  • status: waiting | serving | held | done | cancelled

queue_calls

  • queue_id, window_id
  • called_time; finished_time null = open call

Relationships used in operation

A service has many windows, tickets, and daily counters. A window has at most one staff user and many calls. A ticket may link to one student or to a walk-in issuer. Each call belongs to one ticket and one window. Reports use done tickets and the latest completed call only.
